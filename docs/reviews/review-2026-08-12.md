### Cross-artifact contradictions found

**C2-1 (Major) — two names for the same dispatch call.**
`docs/concepts/commands.md` § "Sending Commands (Functionality Layer)" owns the idiom and states it:

> `docs/concepts/commands.md:123` — "Inside a saga step, dispatch a command with `commandGateway.send(...)`. The return type is `Object` — cast to the expected DTO for read commands"

Every snippet in `sagas.md` (15 sites), `commands.md` (5 sites) and the `architecture.md` Request
Lifecycle uses `send`. Two files use a different method name for the identical call:

> `docs/architecture.md:225` — "`{Aggregate}Dto dto = ({Aggregate}Dto) commandGateway.sendAndCollect(new Get{Aggregate}ByIdCommand(id));`"
> `docs/concepts/rule-enforcement-patterns.md:86` — "`this.{publisher}Dto = ({Publisher}Dto) commandGateway.sendAndCollect(`"

`rule-enforcement-patterns.md` is internally split: lines 86 and 133 use `sendAndCollect`, lines 375,
385 and 386 use `send`. Eight `sendAndCollect` sites total (`architecture.md` 225, 229, 230, 244, 246,
251; `rule-enforcement-patterns.md` 86, 133). Which name the framework actually exposes cannot be
settled from within this skill's review set (Hard Rule 5 excludes `simulator/`), but the artifacts
disagree on their own terms, and `commands.md` is the owning section.

**C2-2 (Major) — `session-a.md` has no subheading for two file kinds `classify-and-plan` puts in its row.**
`session-a.md` § Produce claims authority over the session's output:

> `session-a.md:48` — "plan.md is a blueprint, not a manifest: the `###` subheadings below are the authority on what this session must emit"

`classify-and-plan/SKILL.md` emits two file kinds into that row that no `###` subheading describes:

> `classify-and-plan/SKILL.md:508–511` — "every `× N` collection snapshot → one `aggregate/{CollectionSnapshotEntity}.java` **and** one `aggregate/{CollectionSnapshotEntity}Dto.java`; a single snapshot **with** a non-empty 'Updated on event' → one `aggregate/{SubscribingSnapshotEntity}.java`, no Dto"

`session-a.md`'s subheadings are: `{Aggregate}.java`, "Owned entity classes" (scoped to "each entity
owned by this aggregate (listed in plan.md aggregate section)", i.e. §1 entities), "Domain enums",
`Saga{Aggregate}.java`, `{Aggregate}SagaState.java`, `{Aggregate}Factory.java`,
`Sagas{Aggregate}Factory.java`, `{Aggregate}CustomRepository.java`,
`{Aggregate}CustomRepositorySagas.java`, `{Aggregate}Repository.java`, `{Aggregate}Dto.java`,
`{Aggregate}IntraInvariantTest.groovy`, "Error message constants", "Domain sentinel constants",
`{Aggregate}ServiceApplication.java`. Snapshot entities and their Dtos appear in none of them —
`{Aggregate}Dto.java` is the aggregate's own DTO. The snapshot-entity Dto is nonetheless consumed
downstream:

> `docs/concepts/sagas.md:457` — "`this.{members}.add(new {Aggregate}{Member}Dto({member}Dto.getAggregateId(), /* cached fields */));`"

An agent taking `session-a.md` at its word emits neither file; one taking plan.md at its word emits
them with no guidance on their contents.

**C2-3 (Major) — the canonical `EventProcessing` call drops the mandated version argument.**
`docs/concepts/events.md` makes the publisher version a mandatory parameter of every ByEvent mutation:

> `events.md:286–290` — "**Always advance the cached publisher version.** Every ByEvent mutation must stamp the cached publisher version from `event.getPublisherAggregateVersion()` alongside whatever payload fields it applies … The service method takes the version as a parameter"

The same file's Canonical Wiring Snippet, which § Produce of `session-d.md` names as the per-file
structure for the session, passes one argument:

> `events.md:246` — "`<consumer>Functionalities.<operation>ByEvent(aggregateId, event.get<RelevantField>());`"
> `session-d.md:130` — "`{aggregate}Functionalities.{updateMethod}ByEvent(aggregateId, event.get{RelevantField}());`"

The § ByEvent sagaState guard snippet (`events.md:263`) is open-ended (`(Integer aggregateId, ...)`),
so it does not settle the call site. Followed literally, the version never reaches the service method,
the subscription's `subscribedVersion` never advances, and the redelivery backlog `events.md:301`
describes never converges — a silent runtime defect, not a build failure.

**C2-4 (Minor) — the two session→test-file maps disagree.**
`docs/workflow.md:92` lists "T4 Compensation | `{Operation}CompensationTest.groovy` | 2.N.c".
`implement-aggregate/SKILL.md:16–22`, describing itself as the map of "each session to the test

**C2-5 (Minor) — T3 template names a read method the session skills do not create.**

`session-b.md:55` mandates "`get{Aggregate}ById` unconditionally"; no session produces a

**C2-6 (Minor) — four session sub-files restate a rule owned by `session-completion.md`.**
`_shared/session-completion.md` § "Tick the checkbox" owns ticking and adds the slice rule
("Single-agent mode: … tick the session checkbox **and** every slice sub-checkbox under it").
`session-a.md`, `session-b.md`, `session-c.md` and `session-d.md` each carry their own "Tick the

checkbox line including its `— {SessionName}` label, so they do not mis-match a slice sub-checkbox;
the defect is a weaker duplicate of a single-owner rule, against this skill's own single-owning-file
