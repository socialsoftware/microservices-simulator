## Application-wide facts

Three properties of this spec pair shape every session below, so they are stated once here rather
than repeated per aggregate.

- **No domain events.** §4 of the aggregate grouping is empty by decision, not omission (§3
  "Consistency policy: no cascade"). No aggregate publishes or subscribes, so **no aggregate gets a
  session `d`**, no `EventSubscription` subclass is written, and every `getEventSubscriptions()`
  override returns an empty set. Phase 2 is **24 sessions (8 x `a b c`)**, not 32.
- **No cached version fields.** Every §2 row's "Updated on event" reads `n/a`, so no aggregate ever
  builds an `EventSubscription` and none caches a publisher `version`. Per `/classify-and-plan`
  Step 3.d, an `n/a` row gets no version field at all.
- **No rule is P2.** Every §3.2 rule is a precondition that held at operation time, enforced by a
  saga fetch that fails (P4a), a service guard (P3), or a value the saga computes and passes into the
  aggregate it constructs (P4b). The T3 subscription test type goes unexercised in this application;
  that is the acknowledged cost of the no-cascade decision.

**Shared domain enum.** `DocumentType` is named by User, Contacts and Order, so it is emitted once at
`{src}enums/DocumentType.java` and imported by all three (`session-a.md` § "Domain enums"). Session
2.3.a creates it; sessions 2.5.a and 2.8.a import it unchanged. Every other enum is named by exactly
one aggregate and stays in that aggregate's own package.

`{src}` = `applications/trainticket/src/main/java/pt/ulisboa/tecnico/socialsoftware/trainticket/`

## Rule Classification

All §3.2 rules from trainticket-domain-model.md classified by docs/concepts/rule-enforcement-patterns.md.

| Rule name | Pattern | Implementation note |
|-----------|---------|---------------------|
| STATIONS_EXIST (Route) | P4a | Construction prerequisite. `CreateRoute` / `UpdateRoute` send one `GetStationByIdCommand` per `stationAggregateId` in the request; `aggregateLoadAndRegisterRead` resolves through `findNonDeletedSagaAggregate`, so a missing or soft-deleted Station throws and aborts the saga before any mutation. The same fetch supplies the `stationName` cached on each `RouteStation`. Add the P4 comment at the data-assembly step; add no service guard. |
| UNIQUE_STATION_NAME | P3 | Own-table uniqueness. `StationService.createStation` / `updateStation` read all latest-active Stations via `StationCustomRepository` and throw `DUPLICATE_STATION_NAME` when another active Station holds `name`. Runs at the top of the method inside `@Transactional(SERIALIZABLE)`, before any `createStationCopy`. |
| ROUTE_AND_TRAIN_TYPE_EXIST (Trip) | P4a | Construction prerequisite. `CreateTrip` sends `GetRouteByIdCommand` and `GetTrainTypeByIdCommand`; either fetch throws when its target is missing or soft-deleted, aborting the saga. The Trip block only - the PriceConfig block of this rule was dropped at the §9 review and is not in §3.2. |
| UNIQUE_TRIP_NUMBER | P3 | Own-table uniqueness. `TripService.createTrip` reads all latest-active Trips and throws `DUPLICATE_TRIP_NUMBER` when another active Trip holds `tripNumber`. `tripNumber` is `final`, so no check is needed on the update path. |
| UNIQUE_PRICE_CONFIG_PER_ROUTE_AND_TRAIN_TYPE | P3 | Own-table uniqueness over a compound key. `PriceConfigService.createPriceConfig` reads all latest-active PriceConfigs and throws `DUPLICATE_PRICE_CONFIG` when another active one holds the same `(routeAggregateId, trainTypeAggregateId)` pair. Both ids are local fields, so no cross-aggregate read is involved despite Route and TrainType appearing in the rule's Entities cell. This is the key `GetPriceConfigByRouteAndTrainType` assumes is unique. |
| UNIQUE_USER_NAME | P3 | Own-table uniqueness. `UserService.createUser` reads all latest-active Users and throws `DUPLICATE_USER_NAME` when another active User holds `userName`. `userName` is `final`, so no check is needed on the update path. |
| TRIP_EXISTS (Order) | P4a | Construction prerequisite. `PreserveTicket` sends `GetTripByIdCommand`; the fetch throws when the Trip is missing or soft-deleted. Its result also carries `startTime` for DEPARTURE_TIME_MATCHES_TRIP and the route and train-type ids the later fetches key on. |
| CONTACTS_EXIST (Order) | P4a | Construction prerequisite. `PreserveTicket` sends `GetContactsByIdCommand`; the fetch throws when the Contacts record is missing or soft-deleted. Its result also carries the passenger identity frozen onto the Order and the `userAggregateId` that CONTACTS_BELONG_TO_ACCOUNT compares. |
| CONTACTS_BELONG_TO_ACCOUNT (Order) | P3 | DTO field validation. `OrderService.preserveTicket` compares the request's `userAggregateId` against `contactsDto.getUserAggregateId()` and throws `CONTACTS_NOT_OWNED_BY_ACCOUNT` when they differ. Both sides are already in hand - no User read is performed and §4 declares none. The guard lives in the service, never in the saga step. |
| ENDPOINTS_ON_TRIP_ROUTE (Order) | P3 | DTO field validation. `PreserveTicket` fetches the Trip's Route (`GetRouteByIdCommand` on `tripDto.getRouteAggregateId()`) and passes `RouteDto` to `OrderService.preserveTicket`, which resolves `fromStationName` and `toStationName` against the route's `RouteStationDto` set and throws unless both are present and `sequence(from) < sequence(to)`. No Station read: the predicate resolves entirely from `RouteStation.stationName` and `RouteStation.sequence`. |
| PRICE_CONFIG_EXISTS (Order) | P4a | Construction prerequisite. `PreserveTicket` sends `GetPriceConfigByRouteAndTrainTypeCommand(tripDto.routeAggregateId, tripDto.trainTypeAggregateId)`; `PriceConfigService` throws `PRICE_CONFIG_NOT_FOUND` when no active configuration exists for the pair, aborting the booking. This is a deliberate departure from the benchmark (finding F5), not a reproduction. Add the P4 comment at the step. |
| PRICE_MATCHES_TARIFF (Order) | P4b | Construction invariant. The booking saga computes `price` once, as `(distanceFromStart(to) - distanceFromStart(from)) x rate` from the Route fetched for ENDPOINTS_ON_TRIP_ROUTE and the PriceConfig fetched for PRICE_CONFIG_EXISTS, picking `firstClassPriceRate` for `FIRST_CLASS` and `basicPriceRate` for `SECOND_CLASS`, and passes that single value into the Order it constructs. `Order.price` is `final` and has no other source, so the equality holds by construction. No guard; add the P4 comment at the construction step. |
| DEPARTURE_TIME_MATCHES_TRIP (Order) | P4b | Construction invariant. The saga combines the request's `travelDate` with `tripDto.getStartTime()` into `departureTime` and passes it into the Order it constructs. `Order.departureTime` is `final` and has no other source. No guard; add the P4 comment at the construction step. |
| SEAT_CAPACITY_NOT_EXCEEDED | P3 | Own-table count against a saga-supplied limit. `OrderService.preserveTicket` counts active, non-cancelled Orders matching `(tripAggregateId, travelDate, seatClass)` via `OrderCustomRepository` and throws `SEAT_CAPACITY_EXCEEDED` unless `count < capacity`. Enforce the predicate exactly as §3.2 phrases it - **pre-mutation, strict `<`, excluding the order being created**; transcribing it as a post-state `<=` admits `capacity + 1` bookings. The `capacity` scalar reaches the service as a saga-passed value (**P4b**), fetched from the Trip's TrainType; OrderService never reads TrainType itself. Corrects benchmark defect F1. |
| SEAT_NUMBER_UNIQUE_PER_DEPARTURE | P3 | Own-table uniqueness over a compound key. `OrderService.preserveTicket` rejects a `seatNumber` already held by an active, non-cancelled Order for the same `(tripAggregateId, travelDate, seatClass)`. The saga allocates the lowest free number in `[1, capacity]` by reading the same rows, so the guard is the check that the allocation is honoured under concurrency, not a second allocator. |
| SEAT_NUMBER_WITHIN_CAPACITY (Order) | P3 | Guard over a saga-supplied scalar, reading no rows. `OrderService.preserveTicket` throws unless `1 <= seatNumber <= capacity`, with `capacity` the same value SEAT_CAPACITY_NOT_EXCEEDED uses (`firstClassSeats` for `FIRST_CLASS`, `economyClassSeats` for `SECOND_CLASS`). This also covers the seat-class case: when `capacity` is `0` the interval `[1, 0]` is empty, so no seat can be allocated for a class the train type does not offer. |

**Pattern totals:** P4a 5, P4b 2, P3 9, P2 0, needs-review 0, deferred 0.

### §3.1 rules - all P1

Every §3.1 rule is an intra-invariant in the owning aggregate's `verifyInvariants()`, per
`rule-enforcement-patterns.md` § Decision Guide Step 1. Listed per aggregate below; none of them
needs a service guard, and none may be duplicated at another pattern.

| Aggregate | P1 rules |
|-----------|----------|
| Station | STATION_STAY_TIME_NON_NEGATIVE |
| TrainType | TRAIN_TYPE_NAME_FINAL*, TRAIN_TYPE_SEATS_NON_NEGATIVE, TRAIN_TYPE_HAS_SEATS, TRAIN_TYPE_SPEED_POSITIVE |
| User | USER_NAME_FINAL*, USER_DOCUMENT_NUMBER_PRESENT |
| Route | ROUTE_HAS_AT_LEAST_TWO_STATIONS, ROUTE_SEQUENCE_CONTIGUOUS, ROUTE_DISTANCES_MONOTONIC, ROUTE_FIRST_DISTANCE_IS_ZERO, ROUTE_STATIONS_DISTINCT, ROUTE_ENDPOINTS_MATCH_STATION_LIST |
| Contacts | CONTACTS_DOCUMENT_NUMBER_PRESENT |
| Trip | TRIP_NUMBER_FINAL*, TRIP_START_BEFORE_END |
| PriceConfig | PRICE_RATES_POSITIVE |
| Order | ORDER_STATUS_TRANSITION, ORDER_PRICE_POSITIVE, ORDER_SEAT_NUMBER_POSITIVE, ORDER_DEPARTURE_AFTER_PURCHASE, ORDER_CANCELLATION_FIELDS_SET, ORDER_REFUND_AMOUNT, ORDER_CONTRACT_FIELDS_FINAL* |

**\* Immutability rules are enforced by Java `final` fields and the absence of setters, not by a
`verifyInvariants()` predicate** - the domain model states this explicitly for `TRAIN_TYPE_NAME_FINAL`,
`TRIP_NUMBER_FINAL`, `USER_NAME_FINAL` and `ORDER_CONTRACT_FIELDS_FINAL`. Do not write a predicate
comparing the field against `getPrev()`; declare the field `final`, assign it in the constructor and
the copy constructor, and emit no setter. `ORDER_CONTRACT_FIELDS_FINAL` covers `boughtDate`,
`travelDate`, `departureTime`, `tripNumber`, `fromStationName`, `toStationName`, `seatClass`,
`seatNumber`, `contactsName`, `contactsDocumentType`, `contactsDocumentNumber`, `price`, and the
`tripAggregateId` / `contactsAggregateId` / `userAggregateId` references. Only `status`,
`refundAmount` and `cancelledTime` are mutable on Order.

Two Order rules carry a trap worth restating where the implementing agent will see it:

- **ORDER_STATUS_TRANSITION** predicates on `getPrev()`: `prev == null` requires `status == NOTPAID`;
  otherwise the edge `prev.status -> status` must be one of `NOTPAID -> {PAID, CANCELLED}`,
  `PAID -> {COLLECTED, CANCELLED}`, `COLLECTED -> {USED}`, with `USED` and `CANCELLED` terminal.
  `status == prev.status` is always permitted - every non-status mutation on an Order re-commits the
  same value.
- **ORDER_REFUND_AMOUNT** fires only on the cancelling commit, guarded by
  `status == CANCELLED && (prev == null || prev.status != CANCELLED)`. Without that conjunct,
  `DeleteOrder` on an order cancelled while `NOTPAID` re-checks the rule, falls into the paid branch
  and demands `price x 0.80` from an order correctly refunded `0`.
