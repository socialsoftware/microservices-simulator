## Rule Classification

### §3.2 — Cross-entity rules

All §3.2 rules from `quizzes-full-2-domain-model.md`, classified per
`docs/concepts/rule-enforcement-patterns.md` § Decision Guide.

| Rule name | Pattern | Implementation note |
|-----------|---------|---------------------|
| REMOVE_NO_STUDENTS | P1 | `Execution.students` is an owned collection, so the predicate reads only local state. `Execution.verifyInvariants()`: `state == DELETED ⟹ students.isEmpty()`. `DeleteExecution` must clear the roster in the same operation. |
| NO_DUPLICATE_COURSE_EXECUTION | P3 | Own-table uniqueness. `ExecutionService.createExecution()` guards on `executionCustomRepository`/`ExecutionRepository` lookup by `(acronym, academicTerm)` over ACTIVE executions, inside `@Transactional(SERIALIZABLE)`, before any mutation. |
| INACTIVE_USER | P3 | DTO field validation. `EnrollStudentInExecutionFunctionalitySagas` fetches `UserDto` via `GetUserByIdCommand`; `ExecutionService.enrollStudent()` throws if `!userDto.isActive()` before mutating. |
| STUDENT_ALREADY_ENROLLED | P1 | `Execution.students` is local. `Execution.verifyInvariants()`: all `ExecutionStudent.userAggregateId` values are distinct. Do **not** duplicate as a service guard. |
| USER_EXISTS (Execution) | P2 | `Execution` subscribes to `DeleteUserEvent` per its `User × N` snapshot; the handler deactivates/removes the matching `ExecutionStudent`. Eventual (~1 s). Never blocks. |
| CANNOT_DELETE_LAST_EXECUTION_WITH_CONTENT | — (deferred) | Deferred by the domain model — do not implement. No pattern is assigned and no session produces code for it. Revisit only if a future revision of §3.2 gives it an Entities/Predicate table. |
| TOPIC_BELONGS_TO_QUESTION_COURSE | P1 | Both `Question.courseAggregateId` and each `QuestionTopic.courseAggregateId` are cached locally. `Question.verifyInvariants()`: `∀t ∈ topics: t.courseAggregateId == this.courseAggregateId`. |
| TOPICS_EXIST (Question) | P2 | `Question` subscribes to `DeleteTopicEvent` per `QuestionTopic`; the handler removes or marks the stale topic reference. |
| QUESTION_EXISTS (Quiz) | P2 | `Quiz` subscribes to `DeleteQuestionEvent` per `QuizQuestion`; the handler invalidates the quiz and publishes `InvalidateQuizEvent`. |
| COURSE_EXECUTION_EXISTS (Quiz) | P2 | `Quiz` subscribes to `DeleteCourseExecutionEvent` on its `QuizExecution` snapshot; the handler removes the quiz. |
| UNIQUE_QUIZ_ANSWER_PER_STUDENT | P3 | Own-table uniqueness. `QuizAnswerService.createQuizAnswer()` reads its own table for an existing ACTIVE `QuizAnswer` with the same `(quizAggregateId, userAggregateId)` and throws before mutating. |
| QUESTION_ALREADY_ANSWERED | P1 | `QuizAnswer.questionAnswers` is local. `QuizAnswer.verifyInvariants()`: all `QuestionAnswer.questionAggregateId` values are distinct. |
| ANSWER_MATCHES_CORRECT_OPTION | P1 | `correctOptionKey` is cached on `QuestionAnswer` at create time, so the predicate reads only local state. `QuizAnswer.verifyInvariants()`: `∀qa where qa.optionKey != null: qa.correct == (qa.optionKey == qa.correctOptionKey)`. |
| COURSE_EXECUTION_SAME_QUIZ_COURSE_EXECUTION | P3 | DTO field validation. `CreateQuizAnswerFunctionalitySagas` fetches `QuizDto` via `GetQuizByIdCommand`; `QuizAnswerService.createQuizAnswer()` throws if `quizDto.getExecutionAggregateId()` differs from the supplied `executionAggregateId`. The quiz's execution id is **not** cached on `QuizAnswer`, so this cannot be P1. |
| USER_EXISTS (QuizAnswer) | P2 | `QuizAnswer` subscribes to `DeleteUserEvent` and `DisenrollStudentFromCourseExecutionEvent`; the handlers mark the answer session's student reference stale. |
| QUIZ_EXISTS (QuizAnswer) | P2 | `QuizAnswer` subscribes to `InvalidateQuizEvent` on its `QuizAnswerQuiz` snapshot; the handler removes the answer session. |
| COURSE_EXECUTION_EXISTS (QuizAnswer) | P2 | `QuizAnswer` subscribes to `DeleteCourseExecutionEvent` on its `QuizAnswerExecution` snapshot; the handler removes the answer session. |
| CREATOR_IS_NOT_ANONYMOUS (Tournament) | P1 | `TournamentCreator.userName` / `userUsername` are cached locally. `Tournament.verifyInvariants()`: neither equals `"ANONYMOUS"`. |
| CREATOR_COURSE_EXECUTION (Tournament) | P3 | DTO field validation. `CreateTournamentFunctionalitySagas` fetches `ExecutionDto` via `GetExecutionByIdCommand`; `TournamentService.createTournament()` throws unless the creator's `userAggregateId` appears among `executionDto.getStudents()`. |
| PARTICIPANT_COURSE_EXECUTION (Tournament) | P3 + P2 | Two moments, two mechanisms, as the predicate states. **P3 at add time:** `AddParticipantFunctionalitySagas` fetches `ExecutionDto`; `TournamentService.addParticipant()` throws unless the participant is enrolled. **P2 afterwards:** `Tournament` subscribes to `DisenrollStudentFromCourseExecutionEvent` (anchored on its `TournamentExecution` snapshot) and the handler drops the matching participant. Not a duplicated check — neither alone keeps the predicate true. |
| TOPIC_COURSE_EXECUTION (Tournament) | P1 | Local by construction of the snapshots: `TournamentExecution.courseAggregateId` and each `TournamentTopic.courseAggregateId` are cached. `Tournament.verifyInvariants()`: `∀t ∈ topics: t.courseAggregateId == execution.courseAggregateId`. Dropping either cached field turns this into a cross-aggregate check (see grouping §5). |
| QUIZ_COURSE_EXECUTION_CONSISTENCY (Tournament) | P4b | `CreateTournamentFunctionalitySagas` creates the Quiz itself and passes the **same** `executionAggregateId` to `CreateQuizCommand` and to `CreateTournamentCommand`. No enforcement code; add the mandatory saga comment naming the rule. |
| START_TIME_AVAILABLE_DATE / END_TIME_CONCLUSION_DATE (Tournament) | P4b | The same saga derives `availableDate = startTime` and `conclusionDate = endTime` when it sends `CreateQuizCommand`, and `UpdateTournamentFunctionalitySagas` re-sends both values to `UpdateQuizCommand`. No enforcement code; saga comment required at both sites. |
| NUMBER_OF_QUESTIONS / QUIZ_TOPICS (Tournament) | P4b | The saga selects exactly `numberOfQuestions` questions drawn from the tournament's topics and passes them to `CreateQuizCommand`. No enforcement code; saga comment required. |
| CREATOR_EXISTS / PARTICIPANT_EXISTS (Tournament) | P2 | `Tournament` subscribes to `DeleteUserEvent` and `AnonymizeStudentEvent` for the creator snapshot and per participant; the handlers refresh or invalidate the cached user reference. |
| TOPIC_EXISTS (Tournament) | P2 | `Tournament` subscribes to `DeleteTopicEvent` per `TournamentTopic`; the handler removes the stale topic. |
| QUIZ_EXISTS (Tournament) | P2 | `Tournament` subscribes to `InvalidateQuizEvent` on its `TournamentQuiz` snapshot; the handler invalidates the tournament. |
| COURSE_EXECUTION_EXISTS (Tournament) | P2 | `Tournament` subscribes to `DeleteCourseExecutionEvent` on its `TournamentExecution` snapshot; the handler removes the tournament. |
| QUIZ_ANSWER_EXISTS (Tournament) | P2 | `Tournament` subscribes to `QuizAnswerQuestionAnswerEvent`; the handler updates the matching participant's `TournamentParticipantQuizAnswer` statistics (`answered`, `numberOfAnswered`, `numberOfCorrect`) and sets `firstAnswerTime` from the event payload **once** (idempotent), never from `now()`. |

**Pattern totals (§3.2):** P1 = 7, P2 = 12 (13 counting the P2 half of PARTICIPANT_COURSE_EXECUTION),

are unnamed snapshot-seeding fetches, listed per aggregate under "Cross-aggregate prerequisites".

## Snapshot class decisions (grouping §2)

Applied rule: every `× N` snapshot gets an entity class **and** a Dto; a single snapshot that
subscribes to at least one event gets an entity class and **no** Dto; a single snapshot whose
"Updated on event" is `n/a` gets **no file** and is cached as plain fields on the aggregate.

| Aggregate | Snapshot of | Kind | Emitted |
|---|---|---|---|
| Topic | Course | single, `n/a` | none — `courseAggregateId` field on `Topic` |
| Execution | Course | single, `n/a` | none — `courseAggregateId`, `courseName`, `courseType` fields on `Execution` |
| Execution | User × N | collection | `ExecutionStudent.java` + `ExecutionStudentDto.java` |
| Question | Course | single, `n/a` | none — `courseAggregateId` field on `Question` |
| Question | Topic × N | collection | `QuestionTopic.java` + `QuestionTopicDto.java` |
| Quiz | Execution | single, subscribes | `QuizExecution.java` |
| Quiz | Question × N | collection | `QuizQuestion.java` + `QuizQuestionDto.java` |
| QuizAnswer | Quiz | single, subscribes | `QuizAnswerQuiz.java` |
| QuizAnswer | User/student | single, subscribes | `QuizAnswerStudent.java` |
| QuizAnswer | Execution | single, subscribes | `QuizAnswerExecution.java` |
| QuizAnswer / QuestionAnswer × N | Question | collection | `QuestionAnswer.java` + `QuestionAnswerDto.java` |
| Tournament | Execution | single, subscribes | `TournamentExecution.java` |
| Tournament | User/creator | single, subscribes | `TournamentCreator.java` |
| Tournament | User/participant × N | collection | `TournamentParticipant.java` + `TournamentParticipantDto.java` |
| Tournament | Topic × N | collection | `TournamentTopic.java` + `TournamentTopicDto.java` |
| Tournament | Quiz | single, subscribes | `TournamentQuiz.java` |
| Tournament | QuizAnswer per participant | single (× 1 per participant), subscribes | `TournamentParticipantQuizAnswer.java` |

Names come from §1 of the domain model verbatim where §1 declares the owned value object
(`ExecutionStudent`, `QuestionTopic`, `QuizQuestion`, `QuestionAnswer`, `TournamentCreator`,
`TournamentParticipant`, `TournamentTopic`, `TournamentParticipantQuizAnswer`). Where §1 declares no
value object because the reference is single (`Quiz → Execution`, `QuizAnswer → Quiz/User/Execution`,
`Tournament → Execution/Quiz`) the class is synthesised by qualifying the source name with the owning
aggregate, per the snapshot-entity naming rule.

> **Note for session `a` agents.** §1 of the domain model says single-reference snapshots are "stored
> directly on the aggregate". That note describes where §1 documents the *field list*; it does not
> exempt a **subscribing** single snapshot from having an owned-entity class. Every subscription in
> this application — single or collection — is constructed from a reference object of the same shape,
> which is why `QuizExecution`, `QuizAnswerQuiz`, `QuizAnswerStudent`, `QuizAnswerExecution`,
> `TournamentExecution` and `TournamentQuiz` exist as classes.

> **`OptionDto.java` is listed in 2.5.a** even though `Option` is not a snapshot: `QuestionDto` must
> carry the options for `CreateQuestion` to round-trip, and `correctOptionKey` seeding in the
> `CreateQuizAnswer` saga reads them off `QuestionDto`.

> **Cross-package enum on the Execution snapshot.** `Execution` caches `courseType: CourseType`,
> whose enum is declared in the Course package. R3 permits foreign `{Xxx}Dto` to cross service
> boundaries, and `CourseDto.type` is typed by that enum, so `Execution` imports
> `...microservices.course.aggregate.CourseType` rather than declaring a duplicate. Session 2.4.a
> should escalate as Type 2 if it judges otherwise.

### 2. User

**Write functionalities:**
- `CreateUser(name, username, role)` — create a user account (inactive until activated)
- `ActivateUser(userAggregateId)` — activate a user account so it can be enrolled in executions
- `UpdateUserName(userAggregateId, name)` — update a user's name
- `AnonymizeUser(userAggregateId)` — anonymize a user (set name and username to ANONYMOUS)
- `DeleteUser(userAggregateId)` — soft-delete a user account

**Read functionalities:**
- `GetUserById(userAggregateId)` — retrieve a single user by its aggregate id
- `GetStudents()` — list all users with the STUDENT role
- `GetTeachers()` — list all users with the TEACHER role

**Events published:** `ActivateUserEvent`, `UpdateStudentNameEvent`, `AnonymizeStudentEvent`, `DeleteUserEvent`
**Events subscribed:** —

- `IN_DELETE_USER` — acquired by `DeleteUserFunctionalitySagas` primary lock step

**Write functionalities:**

- `ConcludeQuiz(quizAnswerAggregateId)` — mark a quiz answer session as completed

**Read functionalities:**
- `GetQuizAnswerById(quizAnswerAggregateId)` — retrieve a single quiz answer session by its aggregate id
- `GetQuizAnswerForStudentAndQuiz(userAggregateId, quizAggregateId)` — retrieve the quiz answer session of a given student for a given quiz (reads `Quiz`)

**Events published:** `QuizAnswerQuestionAnswerEvent`

> handling time.

### 8. Tournament

**Write functionalities:**
- `CreateTournament(executionAggregateId, creatorAggregateId, startTime, endTime, numberOfQuestions, topicAggregateIds)` — create a tournament for a course execution (also creates the associated Quiz)
- `AddParticipant(tournamentAggregateId, userAggregateId)` — enroll a student as a tournament participant
- `UpdateTournament(tournamentAggregateId, startTime, endTime, numberOfQuestions, topicAggregateIds)` — update tournament timing or topics
- `CancelTournament(tournamentAggregateId)` — cancel an open tournament
- `DeleteTournament(tournamentAggregateId)` — delete a cancelled or finished tournament, clearing its participant list in the same operation so that `TOURNAMENT_DELETE` holds

**Read functionalities:**
- `GetTournamentById(tournamentAggregateId)` — retrieve a single tournament by its aggregate id
- `GetTournamentsForExecution(executionAggregateId)` — list all tournaments of a course execution
- `GetOpenedTournamentsForExecution(executionAggregateId)` — list the tournaments of a course execution that are currently open
- `GetClosedTournamentsForExecution(executionAggregateId)` — list the tournaments of a course execution that have closed

**Events published:** —
**Events subscribed:** `UpdateStudentNameEvent`, `AnonymizeStudentEvent`, `DeleteUserEvent`, `UpdateTopicEvent`, `DeleteTopicEvent`, `DeleteCourseExecutionEvent`, `DisenrollStudentFromCourseExecutionEvent`, `InvalidateQuizEvent`, `QuizAnswerQuestionAnswerEvent`

**Cross-aggregate prerequisites:**
- `CREATOR_COURSE_EXECUTION` (P3) → `CreateTournamentFunctionalitySagas` data-assembly step
  `GetExecutionByIdCommand` (fetch from `Execution`); validated in
  `TournamentService.createTournament()` against `executionDto.getStudents()`. The same DTO seeds
  `TournamentExecution` (including `courseAggregateId`, which P1 `TOPIC_COURSE_EXECUTION` reads).
- Snapshot seed (P4a) → same saga, `GetUserByIdCommand` (fetch from `User`); seeds
  `TournamentCreator`. `CREATOR_IS_NOT_ANONYMOUS` is then P1 on the cached fields.
- Snapshot seed (P4a) → same saga, `GetTopicByIdCommand` per topic (fetch from `Topic`); seeds each
  `TournamentTopic` including `courseAggregateId`.
- `QUIZ_COURSE_EXECUTION_CONSISTENCY`, `START_TIME_AVAILABLE_DATE / END_TIME_CONCLUSION_DATE`,
  `NUMBER_OF_QUESTIONS / QUIZ_TOPICS` (all P4b) → same saga sends `CreateQuizCommand` with the same
  `executionAggregateId`, `availableDate = startTime`, `conclusionDate = endTime` and exactly
  `numberOfQuestions` questions drawn from the tournament's topics. No enforcement code; add the
  mandatory P4 saga comment naming each rule.
- `PARTICIPANT_COURSE_EXECUTION` (P3) → `AddParticipantFunctionalitySagas` data-assembly step
  `GetExecutionByIdCommand` (fetch from `Execution`); validated in
  `TournamentService.addParticipant()`. Its P2 half is the `DisenrollStudentFromCourseExecutionEvent`
  subscription written in 2.8.d.
- Snapshot seed (P4a) → `AddParticipantFunctionalitySagas`, `GetUserByIdCommand` (fetch from `User`);
  seeds the `TournamentParticipant`.
- `START_TIME_AVAILABLE_DATE / END_TIME_CONCLUSION_DATE` (P4b, update path) →
  `UpdateTournamentFunctionalitySagas` sends `UpdateQuizCommand` with the same new dates.

**Saga states** (`TournamentSagaState`):

- `IN_CANCEL_TOURNAMENT` — acquired by `CancelTournamentFunctionalitySagas` primary lock step
- `IN_DELETE_TOURNAMENT` — acquired by `DeleteTournamentFunctionalitySagas` primary lock step
